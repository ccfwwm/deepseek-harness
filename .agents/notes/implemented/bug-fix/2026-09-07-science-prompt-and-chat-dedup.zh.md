# Agent Note: 保持科研能力提示稳定并去重 Chat 提示词

Status: implemented

[English](2026-09-07-science-prompt-and-chat-dedup.md) | 中文

## 问题

ZeroWall Science 面向模型的身份提示仍描述已经废弃的 MCP 控制工具，并使用分散的 R/Bio 服务名称，因此模型不会被正确引导到紧凑能力目录。Chat 的请求头投影也会在新请求序列、重试和表层重写后再次渲染未变化的系统文本，尽管无状态模型请求仍需要每次携带完整提示词。

## 决策

ZeroWall 基础插件现在发布一条简洁的科研身份提示，说明紧凑的 R、FigureYa、GEO、NHANES 和 Bio 能力族，并要求先使用 `capability_search`，再用精确的 `capability_execute` 执行。提示同时说明产物引用、Manifest/分片文件传输，以及除非用户要求检查图片，否则二进制图片数据不得进入模型上下文。

Chat 的 request-prompt 定义保留持久化请求头，只显示窗口中第一条可用系统提示和之后真正发生文本变化的提示。仅工具变化、重试、文本不变的新序列，以及补入窗口历史产生的重复请求头，都不会新增可见行。Trajectory 和请求重建仍消费所有持久化请求头。

## 备选方案

**只在第一次 HTTP 请求发送系统提示词。** 不采用，因为支持的模型 API 是无状态的，后续请求会丢失当前 developer 指令，除非供应商启用了专用缓存协议。

**第一行之后隐藏所有系统提示词。** 不采用，因为系统文本变化是模型可见行为，必须仍可在 Chat 中检查。

**删除或重写 request/header 事件以减少界面重复。** 不采用，因为请求头是恢复、窗口历史、续接和请求重建所需的持久化 envelope。

## 影响

每个模型请求仍收到完整的当前 system/developer 提示词，会话仍保留自包含的请求快照。普通多步骤对话的 Chat 展示更稳定，同时真正的提示词变化仍然可见。基础提示词保持有限长度，详细能力 schema 继续通过能力目录按需获取。
