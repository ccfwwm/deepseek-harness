# Agent Note：桌面剪贴板路由

## 背景

消息复制控件原先优先使用浏览器 Clipboard API，只有一个聊天组件会在失败后调用 Electron preload 桥接。浏览器写入被拒绝时也可能无法继续进入旧版降级路径，而 preload 调用拒绝会直接中断组件的 Promise 链。

## 决策

`writeClipboard` 现在统一管理所有共享复制控件的完整路由。它依次尝试注入的桌面桥接、浏览器 Clipboard API 和 `execCommand('copy')`。任一路径不可用或拒绝时都会继续下一条路径，只有某个宿主接受完整文本后才报告成功。

消息操作只消费这一份结果，并保留现有的一秒成功提示。组件与辅助函数测试覆盖桌面优先、preload 拒绝、浏览器拒绝、最终降级和全部失败。

## 结果

Electron 会直接使用主进程剪贴板实现，普通浏览器部署继续使用原有路径。其他已经调用 `writeClipboard` 的控件也会获得相同桌面行为，无需在每个组件中加入产品专用逻辑。
